# ACT 与 TurboVLA 真机差异诊断

日期：2026-11-06，Asia/Shanghai。用户确认两者测试时相机未移动、物体摆放范围相同。

## 结论与边界

本轮最强证据支持：TurboVLA 对当前真实观测和执行轨迹的泛化不足，抓取阶段的原始预测就会偏离成功轨迹；当前约每 30 个控制步才更新视觉，以及任务相关平滑规则，会进一步影响闭环纠错。

不能把它直接定性成「训练步数不够」。warm_full_12500 在抽样训练帧拟合很紧。也不能把「DINOv3 过拟合」「缺少显式位置坐标」「L1 条件中位数」当作已证实的唯一原因：目前没有独立留出集训练曲线，也没有对应的受控训练消融。

本次只新增离线诊断脚本和结果。没有改动已有训练/评测实现，没有连接或驱动真机，没有重训。

## 已证实的执行和表示差异

1. ACT smooth 启用真正 temporal ensemble：`scripts/eval_alicia_arms.py:239` 强制每控制步重新预测；`lerobot/src/lerobot/policies/act/modeling_act.py:109` 读取新图像并更新集成。TurboVLA `scripts/eval_alicia_turbovla.py:368`、`:443` 每 30 个控制步才重新预测。在目标 30 Hz 下约一秒开环，实际时间还受推理阻塞影响。
2. TurboVLA 的 `temporal_ensemble_coeff=0.01` 只是启用 blender 的开关，数值不参与指数加权。该 blender 在 `:153` 删除前半块超出上次命令与后半块中位数区间的动作，在 `:179` 通过固定 J1=14 度阈值控制夹爪锁存。这不是 ACT 的时间集成。
3. CPU 最小复现：同一夹爪预测序列 1000→400→900，J1=0 时锁存后的末端输出为 400，J1=20 时为 900。该行为依赖位置，但尚未量化它对本次实际成功率的贡献。
4. ACT 用 640×480 图像，并把二维位置编码送入注意力。TurboVLA 用 256×256，当前 `position_embedding=view` 只额外编码相机身份。DINOv3 内部仍有二维 RoPE，所以不能说 TurboVLA 完全没有位置信息。下游缺少显式 patch 坐标是优先验证的结构假设。
5. 对 DINO 输出后的 patch 顺序随机排列，warm_full 最大关节变化约 0.008 度，freeze 约 0.017 度，符合下游对 token 顺序近似不变。该实验不是移动原图中的物体，不能作为物体平移不敏感的直接证据。

## 本轮排除或降级的解释

- **增强差异**：ACT 的实际保存配置也关闭了图像增强。因此「TurboVLA 无增强」不足以单独解释差距。
- **clean 数据集名字**：ACT 日志为 71 条、24,535 帧；其 checkpoint normalizer 统计与原始数据集一致。`-clean` 名称不能证明它去除了静止帧；清洗目录缺失，尚未逐帧比对。
- **动作范围不够**：最新 ACT 成功轨迹的六关节命令和实测 state 全部位于 TurboVLA min/max 内，不支持这条轨迹因动作范围受限而失败。
- **训练步数直接比较**：ACT BS4×50k 约 20 万个帧锚点，Turbo BS64×8k/12.5k 为 51.2万/80万个。优化步数、样本暴露量和有效学习并非同一指标。
- **L1 本身**：ACT 同样使用 L1 重建项，但另有 CVAE/KL；不能由使用 L1 单独解释 TurboVLA 固定位置抓取。
- **相机变化是唯一原因**：用户确认两模型当前相机和测试范围一致。训练到部署仍可能存在视角偏移，但必须解释为何两者对该偏移的耐受不同。

## 优先验证路径

1. 在相同多位置场景下比较原始预测，并让两模型采用相同的重规划频率及时间集成协议。平滑应只调节动作连续性，不应以固定关节角推断任务阶段。该步骤需要新的真机对照，本轮未执行。
2. 使用按轨迹/物体位置划分的训练与验证集，分接近、闭合、抬起阶段报告误差。已有模型看过全部 71 条轨迹，事后把其中 11 条叫验证集不能测泛化；需要从训练时就留出。
3. 先做显式空间位置编码的单因素对照，再分别测输入分辨率、视觉冻结/学习率和增强。不要同时改全部变量后宣称找到原因。
4. 对已有三个初始化组避免直接以训练 loss 排名真机能力；保留相同初始化、种子、数据划分和执行器的对照。
